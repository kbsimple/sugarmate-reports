### Consistency Label Color Coding

Three semantic states, mapped to existing DaisyUI alert/badge tokens:

| Label | DaisyUI token | Visual treatment |
|-------|--------------|-----------------|
| Consistent | `text-success` / `badge-success` | Green badge label |
| Moderate | `text-base-content/60` / `badge-ghost` | Neutral/muted badge |
| Variable | `text-warning` / `badge-warning` | Amber badge label |

**Rationale:** DaisyUI `text-error` / `badge-error` is reserved for actual error states
(destructive actions, data errors). "Variable" glucose consistency is informational, not an
error — use `warning` (amber), not `error` (red). This matches the existing pattern in
patterns_list.html where `severity == 'significant'` maps to `alert-error` (glucose
danger), while `moderate` maps to `alert-warning` (advisory). The behavioral "Variable"
label is advisory only, so amber is correct.

Accent reserved for:
- Primary CTA button ("Export AGP Report") — pre-existing, not changed
- Active tab radio indicator — DaisyUI handles automatically via `tabs-bordered` / `tabs-lifted`

Destructive: No destructive actions in Phase 4. The `text-error` / `alert-error` token is
not used by this phase.

### 2. Window Size Tab Component

DaisyUI radio-based tabs (no JavaScript required — CSS-only via radio input):

```html
<div class="tabs tabs-bordered" role="tablist">
  <input type="radio" name="behavioral_tabs" role="tab"
         class="tab" aria-label="30 min" checked="checked" />
  <div role="tabpanel" class="tab-content pt-4">
    {# 30-min bucket list #}
  </div>

  <input type="radio" name="behavioral_tabs" role="tab"
         class="tab" aria-label="60 min" />
  <div role="tabpanel" class="tab-content pt-4">
    {# 60-min bucket list #}
  </div>

  <input type="radio" name="behavioral_tabs" role="tab"
         class="tab" aria-label="120 min" />
  <div role="tabpanel" class="tab-content pt-4">
    {# 120-min bucket list #}
  </div>
</div>
```

Tab labels: "30 min", "60 min", "120 min" (short — fits on mobile).
Default active tab: 30 min (first tab, `checked`).
Source: DaisyUI 4.12.14 radio tab pattern; confirmed present in base.html CDN import.

### 3. Bucket Row

One row per time bucket, rendered for all buckets in chronological order (00:00–23:55).
All 288 buckets are rendered per window size; the list is scrollable.

Structure (single bucket row):

```
div.bg-base-200.rounded-lg.p-3.flex.items-center.justify-between
  div.flex.items-center.gap-3
    span.text-sm.font-medium          → bucket label ("12:00–12:30")
    badge [Consistent|Moderate|Variable]  → see color table above
  div.text-right
    p.text-sm.text-base-content/70    → "avg {N} mg/dL"
    details.mt-1
      summary.text-xs.text-base-content/60.cursor-pointer  → "Show score"
      p.text-xs.text-base-content/50.mt-1                  → "Consistency score: {N}% variation across days (lower = more consistent)"
```

Note: `space-y-2` wrapper on bucket list for 8px vertical gap between rows.

---

### 4. Weekday / Weekend Sub-Row (optional, shown when both have sufficient data)

Appended inside the `<details>` block after the CV score, when both weekday and weekend
averages are available:

```
p.text-xs.text-base-content/50  → "Weekday avg: {N} mg/dL · Weekend avg: {N} mg/dL"
```

If only one segment has sufficient data (< 5 days), that segment line is omitted entirely.
If neither has sufficient data, the sub-row is not shown.

## Copywriting Contract

All copy must follow BHVR-06 and INSG-04: wellness framing, no prescriptive language,
no medical claims.

| Element | Copy |
|---------|------|
| Section heading | "Behavioral Patterns" |
| Tab labels | "30 min", "60 min", "120 min" |
| Sub-section heading for insights | "Pattern Insights" |
| Bucket label format | "{HH:MM}–{HH:MM}" (24-hour, en dash, no spaces around dash) |
| Avg glucose display | "avg {N} mg/dL" |
| Details summary trigger | "Show score" |
| CV score detail text | "Consistency score: {N.N}% variation across days (lower = more consistent)" |
| Weekday/weekend detail | "Weekday avg: {N} mg/dL · Weekend avg: {N} mg/dL" |
| Consistent badge label | "Consistent" |
| Moderate badge label | "Moderate" |
| Variable badge label | "Variable" |
| Insufficient data heading | "Not enough data for behavioral patterns" |
| Insufficient data body | "Behavioral patterns require at least 5 days of data in the selected date range. Upload a file covering more days to see time-of-day consistency patterns." |
| Consistent insight title | "Consistent period detected" |
| Consistent insight description | "Your glucose during {bucket_label} is particularly consistent across days." |
| Consistent insight action | "This period may be a useful anchor for your routine — consider noting what contributes to this consistency." |
| Variable insight title | "Variable period detected" |
| Variable insight description | "Your glucose during {bucket_label} tends to vary more across days." |
| Variable insight action | "Consider exploring what differs on days when this period looks higher or lower." |
| Weekday/weekend diff title | "Weekday vs weekend difference" |
| Weekday/weekend diff description | "During {bucket_label}, your weekday glucose ({weekday_avg:.0f} mg/dL) and weekend glucose ({weekend_avg:.0f} mg/dL) follow different patterns." |

| Wellness disclaimer | "Wellness Information Only: These patterns and suggestions are for informational purposes and are not medical advice. Always discuss glucose management with your healthcare provider." |

No destructive actions in Phase 4. No confirmation dialogs required.

## States and Their Visual Treatment

| State | Trigger | Visual |
|-------|---------|--------|
| Normal — data sufficient | `behavioral_patterns` contains results | Tab component with bucket rows |
| Insufficient data | `behavioral_patterns` is None / empty | `alert alert-info` card (no tabs rendered) |
| No notable insights | All periods are "Moderate" | Tab component shown; "Pattern Insights" sub-section omitted |
| Loading | File upload in progress | Pre-existing loading modal (spinner) — no change needed |
| Error | Upload or analysis failure | Pre-existing error toast — no change needed |
