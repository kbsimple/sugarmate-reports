### FINDING-01 — HIGH: `generate_behavioral_suggestions()` is dead code — behavioral suggestions never reach users

**File:** `src/cgm_insights/output/suggestions.py:221`
**Severity:** High

`generate_behavioral_suggestions()` is defined and three `SUGGESTION_TEMPLATES` entries were added for it (`behavioral_consistent`, `behavioral_variable`, `behavioral_weekday_weekend_diff`), but the function is never called anywhere. `upload.py` stores the raw `behavioral_result.model_dump()` in the session; `results.py` passes it directly to the template. The template's "Pattern Insights" sub-section reimplements the same consistent/variable filtering inline with hardcoded wellness copy.

**Impact:** Behavioral suggestions are completely absent from the intended `Suggestion` pipeline. The template copy and the `SUGGESTION_TEMPLATES` copy will diverge silently on any future wording change. The `generate_suggestions()` return value passed to the template never includes behavioral entries.

**Fix:** Call `generate_behavioral_suggestions(behavioral_result)` in `results.py` (or `upload.py`) and merge the result into the `suggestions` list passed to the template. Remove the duplicate inline copy from `behavioral_patterns.html`.

### FINDING-02 — HIGH: Weekday/weekend suggestion fires on first midnight bucket, not the most meaningful difference

**File:** `src/cgm_insights/output/suggestions.py:307`
**Severity:** High

The weekday/weekend diff loop iterates `behavioral_result.patterns` in insertion order (30-min window, `bucket_start=0` first) and `break`s on the first pattern exceeding 10 mg/dL. Since patterns are ordered `[30-min/00:00, 30-min/00:05, ..., 120-min/23:55]`, the midnight 00:00–00:30 bucket fires whenever its diff exceeds threshold — even if a noon bucket has a 5× larger and more actionable difference.

**Impact:** Users with variable sleep schedules see a suggestion about 00:00–00:30 glucose (low-signal) rather than the most behaviorally meaningful time of day.

**Fix:** Before the loop, sort or `max()` over patterns by `abs(weekday_avg - weekend_avg)` (descending) to pick the largest diff. Or filter to daytime-only buckets (e.g., `bucket_start_minute` between 360–1200, i.e., 6am–8pm) before searching.

### FINDING-03 — MEDIUM: `min_days` parameter is not threaded into `_compute_all_buckets` or `_daily_stats`

**File:** `src/cgm_insights/analytics/behavioral_patterns.py:208`
**Severity:** Medium

`analyze_behavioral_patterns(readings, min_days=N)` uses `min_days` only for the outer dataset-level early-return gate (`if total_days < min_days`). The internal helpers `_compute_all_buckets` and `_daily_stats` both hardcode the module constant `MIN_DAYS_FOR_CONSISTENCY = 5`.

**Impact:** Calling with `min_days=3` on a 4-day dataset returns `BehavioralAnalysisResult(insufficient_data=False, patterns=[], total_days=4)` — the outer gate passes but all per-bucket checks still require 5 days, so every bucket is skipped. Callers cannot distinguish "analysis succeeded with no notable periods" from "the parameter was silently ignored." The test suite only exercises `min_days=5` (the default), so this is not caught.

**Fix:** Pass `min_days` through to `_compute_all_buckets(df, window_min, min_days)` and replace both hardcoded `MIN_DAYS_FOR_CONSISTENCY` references with the parameter.

### FINDING-05 — LOW: `--behavioral` flag produces no warning when readings fail to load

**File:** `src/cgm_insights/cli.py:192`
**Severity:** Low

`--insights` has a paired `elif insights and not readings:` branch (line 192) that prints `"Insights require data. No readings available."` The `--behavioral` flag has no equivalent. If the parser returns empty/None, `if behavioral and readings:` is silently skipped.

**Impact:** Users see the GMI caveat line at the bottom but no explanation of why behavioral patterns are absent — inconsistent UX with the `insights` flag.

**Fix:** Add `elif behavioral and not readings: console.print(...)` after the `if behavioral and readings:` block, mirroring the `insights` pattern.

### FINDING-06 — LOW: `if day_type_filter:` treats empty string as no-filter

**File:** `src/cgm_insights/analytics/behavioral_patterns.py:169`
**Severity:** Low

The guard `if day_type_filter:` is falsy for `""`, which would skip the day-type filter and return whole-dataset stats incorrectly. All current call sites pass `"weekday"` or `"weekend"`, so no caller triggers this today.

**Fix:** Change to `if day_type_filter is not None:` to be explicit about intent.
