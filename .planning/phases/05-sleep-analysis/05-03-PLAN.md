# Plan 05-03: Web integration — session, upload, results, and overnight_patterns.html component

## Goal

Wire overnight analysis through the web layer: add `overnight_patterns` field to `SessionData`, call `analyze_overnight_patterns()` in `upload.py`, pass the dict to the results template in `results.py`, create `overnight_patterns.html` component, and include it in `results.html` after the behavioral patterns section.

## Files

### Create

- path: src/web/templates/components/overnight_patterns.html
  description: Jinja2 template component displaying overnight glucose metrics card. Mirrors behavioral_patterns.html structure. Shows: insufficient-data alert, metrics row (mean glucose / TIR / CV / time below range), stability score progress bar with label, weekday vs weekend comparison, excursion summary counts, and wellness disclaimer. Uses DaisyUI stats and progress components. Never uses "sleep" in any user-facing text.

### Modify

- path: src/web/services/session.py
  change: Add `overnight_patterns: Optional[dict] = field(default=None)` to `SessionData`. Add `overnight_patterns: Optional[dict] = None` parameter to `SessionStore.store()` and assign it in `SessionData(...)`.

- path: src/web/routes/upload.py
  change: Add `from cgm_insights.analytics.overnight_patterns import analyze_overnight_patterns`. After the behavioral analysis block, call `analyze_overnight_patterns(readings)` and `overnight_result.model_dump()`. Pass `overnight_patterns=overnight_patterns_dict` to `session_store.store(...)`.

- path: src/web/routes/results.py

Add overnight suggestions to the merged suggestions list. Add `"overnight_patterns": overnight_patterns_data` to the `TemplateResponse` context dict.

- path: src/web/templates/results.html
  change: Add overnight patterns include immediately after the behavioral patterns `{% with %}` block (after line 120).

### Task 3: Create overnight_patterns.html component

Create `src/web/templates/components/overnight_patterns.html`. Mirror the structure of `behavioral_patterns.html` exactly. The component receives `overnight_patterns` (dict from `OvernightAnalysisResult.model_dump()`, or None).

**Required structure** (implement in full):

```jinja
{# Overnight Patterns component.

Parameters:
  - overnight_patterns: dict from OvernightAnalysisResult.model_dump(), or None.
    Keys: mean_glucose (float|null), tir_pct (float|null), cv (float|null),
    tbr_pct (float|null), stability_score (float|null), stability_label (str|null),
    weekday_mean_glucose (float|null), weekend_mean_glucose (float|null),
    weekday_tir_pct (float|null), weekend_tir_pct (float|null),
    excursion_summary (dict), nights_with_data (int), insufficient_data (bool),
    window_label (str).
#}
```

**Insufficient data or missing state** (shown when `overnight_patterns` is None or `insufficient_data` is True):
- DaisyUI `alert alert-info` card
- Heading: "Not enough overnight data"
- Body: "Overnight analysis requires at least 5 nights of data in the 10pm–6am window."
- Do NOT use the word "sleep" anywhere.

**Normal state** (card with all sections):

1. **Card header**: "Overnight Patterns (10pm–6am)" with subtitle showing `{{ overnight_patterns.nights_with_data }} nights analyzed`.

2. **Metrics row** (4-stat DaisyUI `stats` grid or equivalent flex grid):
   - Mean Glucose: `{{ overnight_patterns.mean_glucose | round(0) | int }} mg/dL`
   - Time in Range: `{{ overnight_patterns.tir_pct | round(1) }}%` (label: "70–180 mg/dL")
   - Variability (CV): `{{ overnight_patterns.cv | round(1) }}%`
   - Time Below Range: `{{ overnight_patterns.tbr_pct | round(1) }}%` (label: "<70 mg/dL")

3. **Overnight Stability Score** section:
   - Label: "Overnight Stability Score"
   - DaisyUI `progress` element: `value="{{ (overnight_patterns.stability_score * 100) | round(0) | int }}" max="100"`
   - Display score as percentage and label: `{{ (overnight_patterns.stability_score * 100) | round(0) | int }}% — {{ overnight_patterns.stability_label }}`
   - Use `progress-success` for Stable, `progress-warning` for Moderate variation, `progress-error` for High variation.
   - NEVER display "NGSI" — label must be "Overnight Stability Score" only.

4. **Weekday vs Weekend** (only if both `weekday_mean_glucose` and `weekend_mean_glucose` are not null):
   - Section heading: "Weekday vs Weekend Overnight"
   - Two stat boxes or a simple flex row:
     - "Weekday nights: {{ overnight_patterns.weekday_mean_glucose | round(0) | int }} mg/dL avg"
     - "Weekend nights: {{ overnight_patterns.weekend_mean_glucose | round(0) | int }} mg/dL avg"
   - If `weekday_tir_pct` and `weekend_tir_pct` available, show TIR for each.

5. **Excursion summary** (only if `excursion_summary.total_excursion_nights > 0`):
   - Section heading: "Overnight Patterns of Note"
   - If `sustained_low_nights > 0`: "{{ sustained_low_nights }} of {{ total_nights }} nights had sustained low glucose periods"
   - If `sustained_high_nights > 0`: "{{ sustained_high_nights }} of {{ total_nights }} nights had sustained elevated glucose periods"
   - Use DaisyUI `badge badge-warning` for highs, `badge badge-error` for lows.
   - Do NOT use "hypoglycemia", "hyperglycemia", or any clinical term.

6. **Wellness disclaimer** (always shown at bottom of card):
   ```html
   <div class="bg-base-200 rounded-lg p-2 mt-4">
       <p class="text-xs text-base-content/60">
           <strong>Wellness Information Only:</strong> This analysis uses the 10pm–6am window
           as a proxy for overnight periods. Actual sleep timing varies. This is not medical
           advice — always discuss glucose patterns with your healthcare provider.
       </p>
   </div>
   ```
