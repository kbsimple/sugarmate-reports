## Spacing Scale

DaisyUI + Tailwind utility spacing is used throughout the codebase. All values are multiples of 4.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`gap-1`, `p-1`) | Badge gaps, tight inline elements |
| sm | 8px (`gap-2`, `p-2`) | Pattern row padding, badge row gaps |
| md | 16px (`p-4`) | Card body default padding |
| lg | 24px (`p-6`, `mb-6`) | Section vertical spacing between cards |
| xl | 32px (`max-w-6xl` gutter math) | Layout container padding |
| 2xl | 48px | Major section breaks (not currently used, reserved) |
| 3xl | 64px | Page-level spacing (not currently used, reserved) |

Exceptions:
- Touch targets for tab radio inputs: 44px minimum height enforced by DaisyUI `.tab` class (browser default)
- Chart container height: 300px fixed (`style="position: relative; height: 300px;"`) — not on the spacing scale by design, matches existing `daily_patterns.html`

Source: existing component patterns (`behavioral_patterns.html`, `results.html`, `patterns_list.html`)

## Typography

All type is rendered by the browser using system-ui. DaisyUI provides semantic class sizing.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / description text | 14px (`text-sm`) | 400 (regular) | 1.5 |
| Label / badge / metadata | 12px (`text-xs`) | 400 (regular) | 1.5 |
| Card heading | 18px (`text-lg font-bold`) | 700 (bold) | 1.2 |
| Section heading / card-title | 20px (`text-xl`) | 700 (bold) | 1.2 |

Notes:
- Only two weights used: 400 (regular) and 700 (bold). `font-medium` (500/600) is used for pattern row labels and metric values — treat as 600 semibold in practice.
- `font-semibold` maps to weight 600 in system-ui stacks; used for avg glucose values in row right column.
- No custom font loading. All fonts resolved from system stack.

Source: `base.html` (`Chart.defaults.font.family`), existing component HTML classes

## Color

DaisyUI `light` theme token system. All values are DaisyUI semantic classes, not raw hex, because the theme engine resolves them via `oklch(var(--*))`.

| Role | DaisyUI Class | Hex Approximation | Usage |
|------|--------------|-------------------|-------|
| Dominant (60%) | `bg-base-200` | #e5e7eb (gray-200) | Page background, row backgrounds, section fills |
| Secondary (30%) | `bg-base-100` | #ffffff (white) | Card surfaces, nav bar, tab panels |
| Accent — success | `badge-success` / `text-success` | #22c55e | In-range status badge, "Consistent" pattern badge |
| Accent — warning | `badge-warning` / `alert-warning` | #facc15 | Above-range status badge, "Variable" pattern badge, out-of-range high cards |
| Accent — error | `badge-error` / `alert-error` | #ef4444 | Below-range status badge, severe anomaly alerts |
| Accent — primary | `btn-primary`, `progress-primary` | oklch(var(--p)) | Export AGP button, progress bar, dropzone hover |
| Muted text | `text-base-content/60` | ~#9ca3af | Metadata, descriptions, secondary values |
| Destructive | `alert-error` | #ef4444 | Below-range time windows only (no destructive actions in this phase) |

Accent reserved for:
- In-range badge (`badge-success`) on behavioral pattern rows
- Above-range badge (`badge-warning`) on behavioral pattern rows and out-of-range insight cards
- Below-range badge (`badge-error`) on behavioral pattern rows and out-of-range insight cards
- Export AGP button (`btn-primary`) — existing, not changed

Glucose zone colors (Chart.js `GLUCOSE_COLORS` in `charts.js`):
- very_low: `#ef4444`
- low: `#f87171`
- target: `#22c55e`
- high: `#facc15`
- very_high: `#f97316`

These are used exclusively in chart bars and legend dots. Do not use raw hex elsewhere — use DaisyUI semantic classes.

Range status thresholds (used in both badge logic and out-of-range filter):
- Below range: `avg_glucose < 70` → `badge-error` + "Below Range"
- In range: `70 <= avg_glucose <= 180` → `badge-success badge-outline` + "In Range"
- Above range: `avg_glucose > 180` → `badge-warning` + "Above Range"

Source: `charts.js` (`GLUCOSE_COLORS`, annotation thresholds), `patterns.py` (HIGH/LOW thresholds),
`behavioral_patterns.html` (existing badge classes), `base.html` (DaisyUI CDN version 4.12.14)

## Component Inventory

Components touched or created in this phase:

| File | Action | Description |
|------|--------|-------------|
| `src/web/templates/results.html` | Modify | Add `const patterns = {{ patterns \| tojson }};` to scripts block — one-line fix |
| `src/web/templates/components/behavioral_patterns.html` | Redesign | Remove `<details>`/`<summary>` accordion; add inline range status badge; show weekday/weekend split inline; filter to `bucket_start_minute % 60 == 0` rows within 60-min tab to control density |
| `src/web/templates/components/out_of_range_insights.html` | Create | New priority insights component: filters 60-min window patterns by out-of-range status, renders alert cards with weekday/weekend split, placed above behavioral_patterns tabs in `results.html` |

### behavioral_patterns.html — Redesigned Row Layout

Each pattern row is a flat flex row with two zones: left (time label + badges) and right (avg value + WD/WE split).

Left zone badges — declared order:
1. Consistency badge: `badge-success` ("Consistent") / `badge-warning` ("Variable") / `badge-ghost` ("Moderate") — `badge-sm`
2. Range status badge: `badge-error` ("Below Range") / `badge-success badge-outline` ("In Range") / `badge-warning` ("Above Range") — `badge-sm`

Right zone:
- Avg glucose: `text-sm font-semibold` — `{value} mg/dL`
- WD/WE split (when both values are not null): `text-xs text-base-content/60` — `WD {value} · WE {value}`

No `<details>`, no `<summary>`, no hidden content. All information visible on first render.

Density rule: within the 60-minute window tab, display only rows where `bucket_start_minute % 60 == 0` (hourly boundaries). This yields at most 24 rows. In 30-minute and 120-minute tabs, display only rows where `bucket_start_minute % window_size_min == 0` (non-overlapping boundaries).

### out_of_range_insights.html — New Component

Guard: `{% if behavioral_patterns and not behavioral_patterns.insufficient_data %}`.

Data source: `behavioral_patterns.patterns` filtered to `window_size_min == 60` and `bucket_start_minute % 60 == 0`.

Two sections rendered in order:
1. **Above Range** — patterns where `avg_glucose > 180`, sorted descending by `avg_glucose`
2. **Below Range** — patterns where `avg_glucose < 70`, sorted descending by `avg_glucose`

If neither section has any patterns: component renders nothing (no empty state card needed — the behavioral_patterns tabs already show full detail).

Each insight card:
- Container: `alert alert-warning` (above range) or `alert alert-error` (below range)
- Header line: `{bucket_label} — Above Range` / `{bucket_label} — Below Range` at `font-medium`
- Value line: `avg {avg_glucose rounded to 0} mg/dL` at `text-sm`
- Weekday/weekend split (when both not null): `Weekdays: {wd} mg/dL · Weekends: {we} mg/dL` at `text-sm text-base-content/70`

Placement in `results.html`: Insert the new `{% include %}` block ABOVE the existing behavioral_patterns include block. Users see the actionable summary first, then drill into the full tab breakdown.

All user-facing copy uses wellness language. No medical advice, no prescriptive recommendations.

| Element | Copy |
|---------|------|

| Secondary CTA (unchanged) | "Analyze Another File" (existing btn-outline) |

| No weekday/weekend split available | WD/WE line is omitted (not replaced with error copy) |

| Range badge — in range | "In Range" |
| Range badge — above range | "Above Range" |

## Interaction Contract

This phase is server-rendered HTML only. No JavaScript interaction beyond the existing Chart.js initialization.

| Interaction | Mechanism | Notes |
|-------------|-----------|-------|
| Time-of-Day chart rendering | `DOMContentLoaded` → `initializeCharts()` in `charts.js` | Fix is injecting `const patterns` before `charts.js` is loaded |
| Behavioral pattern tabs (window size) | DaisyUI radio tab `<input type="radio">` — CSS-only | No JS needed; tabs already implemented |
| Out-of-range insight cards | Static server-rendered HTML | No toggle, expand, or animation |
| Inline range status badges | Static server-rendered HTML | No hover state required |
| Weekday/weekend split text | Static server-rendered HTML | Shown/hidden by Jinja2 `{% if %}` guard |

No new JS is added in this phase. No Alpine.js directives are needed. No HTMX calls are added.
